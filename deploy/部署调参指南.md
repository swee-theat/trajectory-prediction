## 1. 前置要求

### 1.1 硬件清单（缺一不可）

| 硬件 | 作用 | 说明 |
|---|---|---|
| Intel NUC | 跑 ROS + 两个节点 | Ubuntu 20.04 + ROS Noetic + Python3.8 |
| Orbbec 深度摄像头 | 感知 | 发布深度图 + `camera_info` |
| Arduino Mega 2560 | 底盘控制 | 接收 NUC 下发的指令驱动电机 |
| 4 麦克纳姆轮底盘 | 执行 | 三自由度 `vx/vy/ω` |
| **底盘驱动节点** | 订阅 `/cmd_vel` 让轮子转 | 在 `实体小车/` 目录，**不在本仓库** |
| **里程计来源** | 发布 `/odom`（20Hz） | 轮速计 + 运动学解算，是预测节点和里程保险丝的输入 |

> ⚠️ 避障节点只负责「决策并发布 `/cmd_vel`」，真正让轮子转的底盘驱动、以及喂给预测节点的 `/odom`，都是外部依赖，必须先跑起来。

### 1.2 软件依赖

```bash
pip3 install -r deploy/requirements_nuc.txt   # onnxruntime>=1.15, numpy>=1.21
```

ROS 包：`astra_camera`（Orbbec 驱动）、`tf`。

### 1.3 契约确认（第一次联调先逐项确认，别急着跑）

1. **深度图话题名**：代码默认 `/camera/depth_registered/image_raw`，驱动实际发布名可能不同 → launch 的 `depth_topic` 覆盖。
2. **camera_info 话题名**：默认 `/camera/depth/camera_info` → `camera_info_topic` 覆盖。
3. **深度编码**：Orbbec 常见 `16UC1`(mm)，也可能是 `32FC1`(m)——代码两者都支持，但需确认。
4. **TF 树**：`map→odom→base_footprint→camera` 必须完整，`base_footprint→camera` 的静态变换要有人发布。
5. **底盘三自由度**：确认底盘驱动能执行 `vy`（麦克纳姆轮横移），这是绕行脱困的物理基础。

## 2. 部署步骤（分 4 阶段，逐阶段验证）

### 阶段 A：环境搭建

```bash
# 1. SSH 到 NUC
ssh <用户>@<小车IP>

# 2. 装 Python 依赖
pip3 install -r requirements_nuc.txt

# 3. 建包目录
mkdir -p ~/ros_space/src/ai_node_master/{models,src,launch}
```

**拷贝文件到 NUC**（Windows 端 [deploy/](.) 目录下）：

| 文件 | 目标路径 |
|---|---|
| `trajectory_model_int8.onnx` | `models/` |
| `ros_node/trajectory_predictor.py` | `src/`（保持可执行） |
| `ros_node/trajectory_predictor.launch` | `launch/` |
| `ros_node/obstacle_avoidance.py` | `src/`（保持可执行） |
| `ros_node/obstacle_avoidance.launch` | `launch/` |

拷贝后 `chmod +x src/*.py` 保持可执行权限。

### 阶段 B：单项验证（一个节点一个节点跑通）

**B1. 摄像头**

```bash
rostopic hz /camera/depth_registered/image_raw   # 确认 ~30Hz 有数据
rostopic echo -n1 /camera/depth/camera_info      # 确认 K 内参、frame_id
rosrun tf view_frames                            # 确认 camera→base_footprint 变换存在
```

**B2. 轨迹预测节点**

```bash
roslaunch ai_node_master trajectory_predictor.launch
rostopic echo -n1 /predicted_best_path           # 有轨迹点输出 = 模型跑通
# RViz 加 /predicted_trajectories/Marker，看 5 条彩色预测轨迹
```

**B3. 避障节点（先静态验证，车架起来别落地）**

```bash
roslaunch ai_node_master obstacle_avoidance.launch
rostopic echo /cmd_vel
# 手动在车前方放/移走障碍物，观察 /cmd_vel 从直行(0.11) → 减速+横移 → 停车 的变化
```

### 阶段 C：闭环联调（车落地，空场地）

按顺序验证四个行为，每步都人工确认安全：

1. **空场地无障碍** → 车直行，`vx=0.11`。
2. **放锥桶 ~1.2m** → 车减速（`vx<0.11`）+ 横移（`vy=±0.05`）绕开。
3. **锥桶逼近 ~0.4m** → 车停车（`vx=0`），保持横移脱困。
4. **连续行驶 5m** → 里程保险丝锁死停车（`vx=vy=0`），`rostopic pub /avoidance_reset std_msgs/Empty` 后恢复。

### 阶段 D：演示验收（对应需求文档预期成果④）

- 完整走一遍「感知→预测→决策→执行」闭环，录像/截图留档。
- 记录实测数据（见第 4 节），这些数据决定第 5 节待办改动的参数取值。

### 阶段 E：两车交互演示（可选，加分项）

两车交互（邻居预测 + 碰撞预警）在实体小车上的演示走「两车通信」方案：第二车把自己的 `/odom` 通过 ROS 多机互传，主车 `trajectory_predictor_pair.py` 订阅并喂给交互模型。**前提：第二辆车也能跑 ROS 并发布 `/odom`（有里程计来源）。** 交互模型需先导出：`python deploy/export_onnx_interaction.py`（产物 `trajectory_model_interaction.onnx`）。

**E1. ROS 多机组网**

- 主车（NUC）跑 `roscore`；
- 第二车节点启动前设置环境变量，把 master 指到主车：
  ```bash
  export ROS_MASTER_URI=http://<主车IP>:11311
  export ROS_IP=<第二车IP>
  ```
- 第二车 odom 话题需带 namespace（如 `/car2/odom`），避免和主车 `/odom` 冲突；若第二车底盘驱动固定发 `/odom`，用 `<group ns="car2">` 包第二车节点重映射。

**E2. 自检（演示前必做）**

```bash
# 主车上看能否收到第二车 odom
rostopic list | grep car2      # 应看到 /car2/odom
rostopic hz /car2/odom          # 应 ~20Hz 有数据
```

**E3. 坐标对齐（先摆位 → 再上电 → 再标 offset）**

两车 odom 都是「各自上电原点清零」的局部坐标，直接相减会错位。演示流程：

1. 把两车摆到目标起始位姿；
2. 两车**同时上电**（odom 各自从 (0,0) 清零）；
3. 测出「第二车原点在主车原点系下的位姿 (dx, dy, dyaw)」，填进 `trajectory_predictor_pair.launch` 的 `neighbor_offset`（两车同点同朝上电则为 `[0,0,0]`）。

> 时钟无需同步：0.11 m/s 下 100ms 相位差仅 1.1cm，可忽略。offset 依赖上电清零，**每次重启都要重标**（或固定摆位 + 固定上电流程复用同一 offset）。

**E4. 演示看点**

- 启动 `trajectory_predictor_pair.launch`，RViz 加 `/predicted_trajectories`（主车 5 模态）和 `/neighbor_predicted_trajectories`（邻居 5 模态）；
- 两车相向/跟车运动，看碰撞预警日志（`未来最小距离 X m < 0.6m`）；
- 拔掉第二车 WiFi 或关机，看主车退化为单车预测并显示「邻居离线」（fail-safe 演示）。

## 3. 调参手册

### 3.1 避障参数总表（`obstacle_avoidance.launch`）

| 参数 | 默认 | 含义 | 调整方向 |
|---|---|---|---|
| `depth_step` | 4 | 像素下采样步长 | 点数多/慢→调大；障碍物小漏检→调小 |
| `depth_max_range` | 5.0 | 有效深度上限(m) | 只需看更近→调小 |
| `ground_thresh` | 0.08 | 地面分割高度(m) | 地面误判为障碍→调大(0.10)；矮障碍漏检→调小 |
| `grid_res` | 0.05 | 栅格分辨率(m) | 计算慢→调大(0.10)；精度不够→调小 |
| `x_min` | 0.15 | 前方检测起点=车头(m) | **卷尺实测 base_footprint 到车头前缘**，实测为准 |
| `x_max` | 3.0 | 前方检测终点(m) | 只看更近→调小 |
| `y_min`/`y_max` | ±1.5 | 横向检测界(m) | 通道更窄→调小 |
| `margin` | 0.15 | 横向安全余量=车半宽+余量(m) | 实际车窄→调小；擦碰→调大 |
| `max_vx` | 0.11 | 直行速度上限(m/s) | 整体更慢→调小（手册 14.3 节 ≤0.12） |
| `slow_start` | 1.5 | 开始减速距离(m) | 减速太晚→调大；太保守→调小 |
| `safe_stop` | 0.4 | 完全停车距离(m) | 停不住撞上→调大 |
| `lat_vy` | 0.05 | 绕行横移速度(m/s) | 绕不开→调大；太猛→调小 |
| `hyst` | 0.2 | 退出滞回(m) | 边界反复横跳→调大 |
| `side_thresh` | 0.05 | 正对中心判定(m) | 方向选错→调小 |
| `clear_frames` | 5 | 退出防抖帧数(0.5s@10Hz) | 单帧漏检导致抖动→调大 |
| `decide_hz` | 10.0 | 决策频率(Hz) | 响应慢→调大；CPU 高→调小 |
| `max_distance` | 5.0 | 里程保险丝(m) | 演示路程更长→调大 |

### 3.2 分症状调参（先对号入座）

| 症状 | 优先调的参数 | 方向 |
|---|---|---|
| 减速太晚 / 撞上桶 | `slow_start`、`safe_stop` | 调大 |
| 绕不开 / 横移不足 | `lat_vy`、`margin` | `lat_vy` 调大、`margin` 调小 |
| 误停车（明明能过却停） | `margin`、`ground_thresh`、`slow_start` | 调小 |
| 地面被误判成障碍物 | `ground_thresh` | 调大（0.08→0.10） |
| 方向选错（往堵的一侧绕） | `side_thresh` | 调小（待办的侧移通道/差阈值会进一步改进） |
| 边界反复横跳 / 抖动 | `hyst`、`clear_frames` | 调大 |
| CPU 高 / 决策卡顿 | `depth_step`、`grid_res`、`decide_hz` | `depth_step`/`grid_res` 调大、`decide_hz` 调小 |
| 跑一会儿自动停车 | `max_distance` 或 `/avoidance_reset` | 调大 / 发 reset 归零 |
| **近场盲区撞桶（<0.4m 突然失明）** | 见第 5 节待办 | 方案 A 栅格滞留 |

### 3.3 预测节点参数（基本不动）

`trajectory_predictor.launch` 的 `obs_len=20`/`pred_len=30`/`num_modes=5` 是**训练时定死的**，改了会和模型不匹配导致预测退化，**不要动**。唯一可切的是 `model_path`：INT8 模型（默认，体积小）↔ FP32 模型（`trajectory_model.onnx`，精度略高）。

## 5. 待办（等实测后一起做，已记录在案）

实测数据回来后统一实施，两批：

**A. 六条安全机制细化**
- `side_occupancy` 改「侧移通道 box」统计（`x∈[x_min,x_min+1.0]`、`y∈[±0.15,±0.65]`）
- `_pick_sign` 加差阈值（差 <3 格视为噪声回退默认右）
- 状态机加 `BLOCKED`（两侧都堵→全零停车，不硬绕）
- 走廊/侧移区间统一 `x∈[x_min, x_min+len]`（修 `x_min` 引入后走廊短 0.15m 的 bug）
- `_shutdown_hook` 连发、抽 `_safe_stop` 防自递归、里程抽 `DistanceFuse`、加 odom 超时 fail-safe、launch `respawn`→false

**B. 近场盲区处理（方案 A：栅格时间滞留）**
- 当前深度链路无 `min_depth`、栅格无时间记忆，障碍物进相机盲区会瞬时消失→误判无障碍→撞桶。
- 方案 A（障碍物格保留 N 秒）纯软件，`N` 按实测盲区距离 + 车速定（预估 1~2s）。
